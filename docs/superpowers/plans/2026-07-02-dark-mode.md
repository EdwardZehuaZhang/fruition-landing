# Site-wide Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the site a deliberate, OS-driven ("neutral ink") dark theme that renders consistently on every device, replacing the accidental mobile auto-inversion.

**Architecture:** Introduce semantic color tokens in `globals.css` that flip inside `@media (prefers-color-scheme: dark)`, exposed as Tailwind v4 theme utilities (`bg-surface`, `text-body`, `border-ui`, …). Sweep all ~183 components off hardcoded colors (`bg-white`, `text-[#242323]`, grey text, grey borders) onto those tokens. Frame light-background imagery with a `FramedMedia` wrapper. No JS, no toggle — pure CSS media query.

**Tech Stack:** Next.js 16 (App Router, Turbopack), Tailwind CSS v4 (`@theme inline` in `globals.css`), React 19, Sanity CMS, Playwright (visual QA).

## Global Constraints

- **This is NOT stock Next.js** — per `AGENTS.md`, read the relevant guide in `node_modules/next/dist/docs/` before writing any Next-specific API (e.g. the `viewport`/`colorScheme` export). Heed deprecation notices.
- **Dark trigger:** `@media (prefers-color-scheme: dark)` only. No toggle, no JS state, no `.dark` class, no persistence.
- **Tailwind v4:** no `tailwind.config`; tokens live in `@theme inline` in `src/app/globals.css`. The `dark:` variant already maps to `prefers-color-scheme: dark` (no custom variant configured) — use it for one-off cases; prefer tokens for systemic colors.
- **Palette (neutral ink):** page `#0f1115`, raised `#1a1d24`, subtle `#161922`, body text `#f2f3f5`, muted `rgba(255,255,255,.62)`, border `rgba(255,255,255,.12)`. Brand purple `#8015e8` / `#ba83f0` unchanged in both modes.
- **No behavior/layout changes** — theming only.
- **Per-task verification:** `npm run typecheck && npm run lint` must pass; visual tasks also require Playwright light+dark screenshots reviewed by a separate QA subagent (see Task 2 for the harness).
- **Commit** after each task.

## The sweep mapping (applied in every sweep task)

| Find (hardcoded) | Replace (token utility) |
|---|---|
| `bg-white` on page/section wrappers | `bg-surface` |
| `bg-white` on cards, dropdowns, modals, raised chips | `bg-surface-raised` |
| `bg-[#ecf1fc]`, light-blue section bg | `bg-surface-subtle` |
| `text-[#242323]`, `text-black`, `text-gray-800/900`, `text-slate-900` | `text-body` |
| `text-[#686b82]`, `text-gray-400/500/600`, `text-[#595959]`, `text-[#666]` | `text-muted` |
| `border-gray-100/200`, `border-[#dedee5]` | `border-ui` |
| brand hexes (`#8015e8`, `#ba83f0`, gradients) | **leave unchanged** |
| one-off non-brand hexes (oranges/blues) | judgment: keep if legible on both surfaces, else add `dark:` variant |

Rule for `bg-white`: default to `bg-surface`; use `bg-surface-raised` only when the element is visually elevated above its section (card, dropdown, modal, floating chip). When unsure, screenshot both.

### Task 2: Playwright light/dark QA harness

**Files:**
- Create: `scripts/qa-darkmode.mjs`
- Test: harness IS the test infrastructure for all later visual tasks.

**Interfaces:**
- Produces: `node scripts/qa-darkmode.mjs <path> [<path>…]` → writes `qa/darkmode/<slug>-light.png` and `-dark.png` against `http://localhost:3007`.

- [ ] **Step 1: Write the harness**

```js
// scripts/qa-darkmode.mjs — screenshot given routes in light + dark
import { chromium } from 'playwright'
import { mkdirSync } from 'node:fs'

const BASE = process.env.QA_BASE || 'http://localhost:3007'
const paths = process.argv.slice(2)
if (!paths.length) { console.error('usage: node scripts/qa-darkmode.mjs /path …'); process.exit(1) }
mkdirSync('qa/darkmode', { recursive: true })

const browser = await chromium.launch()
for (const scheme of ['light', 'dark']) {
  const ctx = await browser.newContext({ colorScheme: scheme, viewport: { width: 1440, height: 900 } })
  const page = await ctx.newPage()
  for (const p of paths) {
    const slug = p === '/' ? 'home' : p.replace(/^\//, '').replace(/\//g, '-')
    await page.goto(BASE + p, { waitUntil: 'networkidle', timeout: 60000 })
    await page.screenshot({ path: `qa/darkmode/${slug}-${scheme}.png`, fullPage: true })
    console.log(`shot ${slug} ${scheme}`)
  }
  await ctx.close()
}
await browser.close()
```

- [ ] **Step 2: Verify it runs** — with dev server up on 3007:

```bash
node scripts/qa-darkmode.mjs /
```
Expected: creates `qa/darkmode/home-light.png` and `qa/darkmode/home-dark.png`. Dark home shows `#0f1115` page bg behind still-unconverted white sections (mixed state expected mid-migration).

### Task 3: `FramedMedia` imagery wrapper

**Files:**
- Create: `src/components/common/FramedMedia.tsx`

**Interfaces:**
- Produces: `<FramedMedia className?>{children}</FramedMedia>` — pass-through in light; in dark wraps children in a subtle light, rounded, bordered card so light-bg media reads as intentional.

- [ ] **Step 1: Write the component**

```tsx
import type { ReactNode } from 'react'

/**
 * Wrap light-background media (screenshots, client logos, CMS images) so they
 * don't glare on dark surfaces. Light mode: transparent pass-through.
 * Dark mode: renders a soft light card behind the media.
 */
export default function FramedMedia({
  children,
  className = '',
}: {
  children: ReactNode
  className?: string
}) {
  return (
    <div className={`dark:bg-white/90 dark:rounded-xl dark:p-2 dark:ring-1 dark:ring-white/10 ${className}`}>
      {children}
    </div>
  )
}
```
